Stage 1: Fetch Data
1.1 Tabular Data
Dataset: Use Hugging Face's synthetic_pii_finance_multilingual dataset (or equivalent) for tabular financial data.
Tech Stack: Python + datasets library (Hugging Face).
Steps:
Load the dataset using Hugging Face's datasets library.
Clean and preprocess the data if required.

1.2 Scraping Text Files
API: Use the Google News API (or alternatives like Bing News API or NewsAPI) to fetch financial or business-related news articles.
Tech Stack: Python + requests or httpx.
Steps:
Set up the API key for the news API.
Fetch at least 100 articles with filters for relevance and recency.
Save the raw articles in JSON format for later processing.

Stage 2: Data Storage
2.1 MongoDB Setup
Database: MongoDB for storage.
Tech Stack: Python + pymongo.
Steps:
Install MongoDB and create a database (e.g., finance_ner).
Create two collections:
tabular_data: Store tabular data as JSON-like documents.
news_articles: Store news articles with metadata (title, date, content).
Write scripts to:
Insert the preprocessed tabular data into tabular_data.
Insert the articles into news_articles.

Stage 3: Agent System
3.1 Named Entity Recognition (NER)
Objective: Fine-tune an open-source LLM for financial/business-oriented NER.
Model: Start with a pre-trained LLM like bert-base-multilingual-cased or roberta-large.
Tech Stack: Python + transformers + datasets.
Steps:
Preprocess tabular data into labeled NER format.
Fine-tune the model using Hugging Face's Trainer API or PyTorch.
Evaluate the model on:
Precision, Recall, and F1 Score for the NER task.
Save the fine-tuned model.

3.2 Retrieval-Augmented Generation (RAG) System
Objective: Build a RAG system to answer queries based on tabular and news data.
Tech Stack: Python + LangChain + OpenAI/LLM of choice.
Steps:
Use a vector store (e.g., FAISS, Weaviate, or Pinecone) for embedding-based retrieval of news data.
Configure LangChain to:
Retrieve relevant news articles and tabular data for queries.
Answer user queries using hierarchical reasoning.
Use the fine-tuned NER model to extract entities and enhance context.

Model Evaluation
Metrics:
LLM: BLEU/ROUGE for generated responses.
NER: F1 score.
System: Response relevance score (manual or automated).

Stage 4: User Interface
4.1 Interface with Gradio
Tech Stack: Python + Gradio.
Features:
Input: Allow users to query using natural language or input a ticker symbol.
Output: Display:
Retrieved tabular data.
Summaries/answers generated by the RAG system.
Steps:
Design a simple Gradio UI with input and output widgets.
Integrate the backend (RAG system) with the UI.
